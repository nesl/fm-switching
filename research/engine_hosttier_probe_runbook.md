## 0. Abort conditions (check ALL, any one = do not start, release the hold, report)
1. A cell start-up in progress or due before the block ends. The probe needs the driver HELD AT A CELL BOUNDARY (section 1b): the previous cell has finished and committed, the driver is idle (nothing runnable), and no cell is queued to start until the hold is released. Never hold or probe during a start-up.
2. GPU 2 not idle after the previous cell's server has FULLY exited: `nvidia-smi -i 2` shows memory.used >= 1000 MiB, util >= 5 percent, or any compute process on GPU 2 (the script's preflight enforces under 1000 MiB, under 5 percent, no compute process on GPU 2). The previous cell's `vllm serve` (ours) must be gone: `ps -u "$(id -un)" -o pid,args | grep -E "vllm serve|vllm.entrypoints|run_live2_real" | grep -v grep` prints nothing. If our own server is still draining, wait; do not kill other users' processes; do not start on GPUs 0, 1 or 3.
2b. GPU identity: `nvidia-smi -i 2 --query-gpu=uuid --format=csv,noheader` must equal GPU-4f1d7e47-e769-a289-4860-e71c0d97267c (the driver's cell GPU). If it differs, STOP: the index and the driver's UUID disagree and the probe could land on another user's GPU. `export CUDA_DEVICE_ORDER=PCI_BUS_ID` before launching, so the script's CUDA_VISIBLE_DEVICES=2 means the same device as `nvidia-smi -i 2`.
3. Another `vllm serve` process alive: the script's preflight refuses ("abort (preflight): another vllm server is running ...") unless `--allow-other-vllm`. READ THIS: the preflight check is `ps -eo pid,args` over ALL USERS on the shared host, matching the substring "vllm serve" or "vllm.entrypoints". Other users run vllm on this host (2026-11-27 03:10 record: GPU 3 held by another user's vllm job, GPUs 0 and 1 also occupied), so the check can abort the probe even though GPU 2 is clean. If it aborts this way nothing has been launched and nothing needs cleaning: re-run with `--allow-other-vllm` ONLY after these manual checks pass and are pasted into the report: (a) `ps -u "$(id -un)" -o pid,args | grep -E "vllm serve|vllm.entrypoints" | grep -v grep` prints NOTHING (no process of ours); (b) every line of `ps -eo pid,user,args | grep -E "vllm serve|vllm.entrypoints" | grep -v grep` belongs to another user and none of those processes holds GPU 2 (`nvidia-smi --query-compute-apps=gpu_uuid,pid --format=csv,noheader` has no row with 4f1d7e47); (c) the script's own GPU 2 compute-process check is not bypassed by the flag (it is a separate check). The flag only disables the vllm-process-name guard; the manual checks replace it. Do not use the flag to get past a guard that names a process of ours.
4. Free host memory below the margin: MemAvailable < 30 GB at 13.5 GiB (45 GB for --host-gib 27). Derivation: mmap 14.5 GB x 1.25 (shm file plus mapped pages) = 18.1 GB, plus 8 GB for pinned buffers, mm cache (text prompts leave it empty) and weight staging, rounded up to 30 GB. Also /dev/shm free must exceed 1.05 x the mmap size (the script checks both). The host has about 1.5 TB RAM and is shared: read MemAvailable and `df -h /dev/shm` at the boundary, not from an earlier note.
5. Port 8131 not free: `ss -ltn | grep -E ":8131 "` must print nothing (cells use 8031; the previous cell's 8031 server must also be gone).
6. The flag diff printed at start is not exactly "argv[6]: committed='8031' probe='8131'" (plus argv[0] only if --vllm-bin is given). The script aborts by itself; do not override.
7. Part A: connector is not OffloadingConnector, the mmap is not a whole number of 4,194,304-byte chunks, or GPU blocks missing: the script aborts (Step 0 invalidators).

## 1b. Hold the driver queue at a cell boundary, and release it (how the H100 holds the driver: the driver does not pause on a file; it idles when nothing is runnable)
The driver (v46 or later) reads its lists at every run boundary and, when nothing is runnable, logs "sweep: nothing runnable now" and polls every 5 minutes (touching $HOME/data/live2/frozen_grid/driver_idle). The H100's established hold is therefore:
1. While the cell before the gap is still running (never during a start-up): note the pre-hold copy of the gated lists. Hold by prefixing the not-yet-started lines of the gated lists in results/orchestration/live2/frozen_test/runs/V6_GATE_OK (and any other list that has runnable lines) with `#HOLD-PROBE`; keep the pre-hold copy outside the tree (the 2026-11-26 'HOLD APPLIED' and 'lists held' records in research/OVERNIGHT_HANDOFF_H100.md are the precedent). Do NOT use the `STOP` file (the driver exits and has to be restarted) and do NOT kill the driver.
2. Stop the pusher (experiments/orchestration/h100_pusher.sh) so no pull or push races the probe's output files; verify local == origin.
3. At the cell boundary confirm: the cell's cell.json is written and committed, the driver log shows "nothing runnable", `driver_idle` exists, no python and no `vllm serve` of ours is running, and GPU 2 is empty (`nvidia-smi -i 2`: under 1000 MiB, no compute process). Only then start section 2. If the driver started another cell instead (the hold missed it), do NOT probe; the cell keeps the GPU.
4. Defensive only: the driver's start path waits `while nvidia-smi --query-compute-apps=gpu_uuid ... | grep -c 4f1d7e47 != 0` before launching a server, so a mistakenly released driver blocks on the probe's server rather than starting on top of it. Do not rely on it.
5. RELEASE after the exit checks of section 4 pass: restore the pre-hold list lines (remove the `#HOLD-PROBE` prefix; re-gate with the new sha256 if V6_GATE_OK lines are sha-keyed, as in the 'HOLD APPLIED' precedent), restart the pusher, and expect the driver to start the next cell within 5 minutes. Record the release time.
