## 3. RTT (Q3)
- Today: LinkSpec.rtt_ms default 44.0 (links.py:39, D75; same pair as StudyE4/E9/CTRL1c). Charged in the emulator: upload arrival = serialise + RTT/2 (links.py upload_s, UplinkQueue.send and _send_question t_arrive), pull message RTT/2 (emulator.py:443,448,553), cloud answer delivery RTT/2 + payload/downlink (emulator.py:452-454). Per-device value is registered to the coordinator (emulator.py:656 -> cstate.py:329 -> NetworkState.rtt_s cstate.py:731). RTT does not occupy the uplink, so it never lengthens a drain.
- The POLICY prices RTT with a CONSTANT: LINK_RTT_S = TRACES.RTT_MS/1000 = 0.044 (v5/cf_cost.py:107-110), read at arms_v6state.py:538,599,601,640, link_sync.py:160, cf_cost.py:184,221. A raised emulator RTT with no change to that constant is "planning at one price while charged another" (CLAUDE.md check 7).
- Khan et al., "How Mature is 5G Deployment? A Year-Long Study of 5G Uplink Performance", IFIP Networking 2024 pp 276-284: Bay Area 5G RTT p90 = 142 ms (quote "142 ms vs. 90 ms at the 90-th percentile", read at source by StudyQCLASS-CENSUS; uplink median 12 Mbps; 80 T-Mobile tests Jul 2022-Jul 2023). The ambiguity of what 90 ms is (LTE?) is not resolved in the repo: FLAG. Khan MEDIAN RTT is NOT in the repo (the 22 ms "ICCCN" median is unidentifiable, EXPERIMENTS.md StudyQCLASS-CENSUS). Other RTT in repo: Irish PINGAVG p50/p90/p99 = 80/120/351 ms (OBSERVED, only 8.1 pct coverage, study_network_tier1.md); Ookla 2026Q3 latency p10/p50/p90 = 17/27/56 ms (idle ping, not application RTT).
- Arithmetic: 142 ms vs 44 ms adds 98 ms per round trip (about 3.3 pct of the 3.0 s deadline); one-way terms +49 ms on question arrival and +49 ms on answer delivery. It shifts slack, not drain length, so a pure RTT regime is the one most at risk of Rule 2 "unexercised"; the positive control (below) must show decisions moved.
- DESIGN, default OFF: harness flag `--link-rtt-ms <x>` (run_live2_real.py, next to :146) + driver v47 token `_rtt<ms>` (integer, whole token, sed `_rtt([0-9]+)_`, refused unless the flag with that exact value is in the launch args; same ARGS-MISMATCH and live-argv/header.json watcher pattern as `_up` v46 l.321-325, l.439-446). Reads: (a) run_live2_real.py:821-830: build `link_by_device` for EVERY device, LinkSpec(uplink_mbps=<_up rate for robo* else default>, rtt_ms=x) so uplink send, pull and answer delivery all move (both directions, RTT/2 each; no downlink-rate change); (b) set the planner constant (cf_cost.LINK_RTT_S = x/1000) once at startup so charged = planned; (c) header.json field `link_rtt_ms` only when set. Uniform over all devices (D75 is uniform), so the dashcam and SS also pay it: that is why each regime needs its own no-outage control. Robots-only (like `_up`) is possible but then the constant mis-prices dashcam: not recommended. No trace change (RTT is an emulator setting, not in the trace dir name).
- Size: about 60-80 lines (flag + link_by_device 15, constant 3-5, driver parse + guard + watcher 30-35, unit test 25). Off-identity proofs: (1) tag-to-args diff over all committed cell lines v46 vs v47 = 0 lines (as v44 did over 568 lines); (2) 300 s dry digests with no flag equal pristine; (3) `_rtt44` equals no-token digest (positive control: the default value must be a no-op).
