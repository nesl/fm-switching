## 3. THE HARM DEFINITION, every quantity with its source
HARM = HARM_pending + HARM_arrival, then `ADMIT iff w_R p_self + FUTURE - HARM > w_R MARGIN_CF_ON_TIME` (cf_forfeit.admit_decision; the committed D218 inequality, `cf_protect_defer.py:228-259`).
HARM_pending: the other robot AND single-shot questions already pending this epoch, `arms_v6cf._pd_others` (rows built from `obs.recall`), priced by `cf_protect_defer.harm_on_time` (cf_protect_defer.py:449) -> `cf_objective.harm_warm_from_queue_delay` (v5/cf_objective.py:809).
HARM_arrival (new), per OTHER device j (robot and single-shot; dashcam excluded, protected via C5 and the rung 4 request leg):
- expected arrivals in the window: `n_j = window / gap_j`; `gap_j` = the rules arm's own causal EWMA gap per device, `_gap_ewma[did]` (arms_v5rules2.py:444), the SAME estimate FUTURE reads (arms_v6cfstep3.py:254) and the same per-device key (`_p_question` reads it).
- window = `min(est_loadaware of the admitted request, HORIZON_WARM_CAP_S)`: the admitted request is in the queue for its own load-aware first-token time, B's committed estimator (`la_arrival_admission.loadaware_est`, :85, = `d162_price.first_token_s`, d162_price.py:82); the cap is `cf_cost.HORIZON_WARM_CAP_S` = 120 s (cf_cost.py:126), the same horizon as FUTURE. (INTERPRETATION FLAGGED, section 8 A: the window is the service time, not the full 120 s.)
- each arrival's first token under the current queue: `loadaware_est(u_j, queued_ahead)` with `u_j` = that device's last question's prompt tokens minus the tokens the cloud has built (`built_tokens_by_session`, the same arithmetic as `_pd_others`) and `queued_ahead` = `la_arrival_admission.queued_ahead(obs)` (the in-flight uncached tokens B itself reads, :72); its slack = that device's last question's own deadline duration (`deadline_s - arrival_s`).
- delay the admission adds: the committed D162 queued-ahead term `QUEUE_TOKEN_S x u_admit` = `d162_price.PER_QUEUE_S` (d162_price.py:48; v5/cf_objective.py:786) times the admitted request's uncached tokens, capped at `HEALTHY_FIRST_TOKEN_BOUND_S` 2.781 s (cf_objective.py:792, D160 (2)), exactly what `harm_warm_from_queue_delay` does for the pending rows; this equals `est_loadaware(u_j, ahead + u_admit) - est_loadaware(u_j, ahead)` because the model is linear in the queue.
- on-time probability: `cf_cost.p_on_time(residuals, est, slack)` (v5/cf_cost.py:306), the committed on-time curve whose margin is `MARGIN_CF_ON_TIME` (the same function FUTURE and p_self use); lost = `p_on(est, slack) - p_on(est, slack - delay)`; value = `w_j x n_j x lost` with `w_j` the live deficit weight (`arms_v6cfr3._weight_of`, floor 1).
Every quantity is committed; nothing needed inventing, so no STOP. One approximation, stated: an expected arrival is delayed by the full added queue term although it may arrive after the admitted work has left the queue (an upper bound on the delay inside the window).
