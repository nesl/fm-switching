# Scheduling policy: design decisions and pinned items

Living log for the scheduler design discussion (started 2026-11-15). Decisions are what we have agreed; hypotheses are expectations to test, NOT design constraints; pinned items are deliberately deferred and must be revisited. The current specification is **v6 = `research/policy_spec_v6.md`** (D165), which supersedes `policy_spec_v4.md` (D59) and `research/policy_spec_v5.md`, and through v4 the earlier v3 and its v3.1 addendum. Later rows revise earlier ones where noted.

## Problem-setting rules (standing; apply to every design, prompt and evaluation)

- MEMORY CAPACITIES ARE INPUTS, NOT CONSTANTS (D56). GPU KV pool and host tier sizes are parameters of the problem. The H100's large host memory is platform specific and must never be treated as a rule or used to argue that a decision is trivial.
- EVIDENCE THAT REACHES THE CLOUD IS NEVER DISCARDED (D56). Every device history lives in one of three tiers: GPU-warm, host-warm, or COLD (raw frames on disk, rebuilt by prefill when needed). "Dropped" means demoted to cold, never deleted.
- WHERE TO STORE EACH HISTORY (GPU / host / cold) IS A CORE DECISION under whatever capacities apply (D56).
- DEVICES NEVER SHARE CACHE ENTRIES in any evaluation (D84): per-device cache salt and per-(device, frame) multimodal UUIDs.

The device-discounted form (multiply by 1 - P(device on time)) is rejected: it asks whether the displaced query goes unanswered, which never happens, and prices harm at about zero. Flash first checks whether the coded on-time-cloud form is weighted by the accuracy gain; if not, the gain weighting is added. (2) ORACLE: each policy is reported as the share of the achievable gain it captures, (policy - device-only floor) / (oracle - device-only floor), on the same questions per seed. Headline oracle = FAIR oracle: perfect knowledge of arrivals, deadlines and measured service times, but only per-type accuracy (the information the policies have). Reference line = HINDSIGHT oracle (also knows per-answer correctness). The oracle must be a provable UPPER BOUND (a relaxation, e.g. capacity from the engine's measured peak throughput plus per-query deadlines and service times), not a heuristic. Computed per memory level. Owner: Orin, offline from committed traces, no new runs. (3) MEMORY SWEEP: 1x, 0.5x (real engine pool, the kv0.5r cells) and 0.25x at seeds s4-s7 for base, rung 3, rung 4 (once rebuilt; reduced-memory rung-4 cells still wait on E1) and the paper baselines; about 48 new cells, about 20 H100 hours.
