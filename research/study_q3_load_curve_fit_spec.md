# `-q3` LOAD-DEPENDENT PER-REQUEST HARM: THE FIT, PRE-DECLARED BEFORE ANY FITTING (2026-11-26T02:38:05Z). No fit has been run.

**User ruling (extends D283).** Neither a constant nor the intercept form: the per-request harm of a touch or background warm is the FITTED per-request first-token delay at the CURRENT load plus the per-uncached-token term, applied to deadline requests queued behind it, deficit-weighted. **A MODELLING ASSUMPTION, with the endogeneity caveat below.**
## Data (rung 3 ONLY, so the fit is not driven by the pricing under test; s4 EXCLUDED so the gate is out of sample)
Committed rung-3 cells (`covex-v6-fair-final`, any same-code replicate) at **1x seeds 5, 6, 7** and **`_kv0.5r_h0.5` seed 5**; every cell named in full; any `source_agreement` verdict starting INVALID refused (read from `header.json`). Unit: each DEADLINE request (dashcam monitor and robot recall; touches, pieces and other background excluded).
## Model, fixed now
y = first-token latency (t_first_token - t_submit) = a + b*uncached + c*U_ahead + g(N_ahead), where N_ahead = number of OTHER requests in flight at the request's submit (submitted earlier, no first token yet) and U_ahead = their summed uncached tokens (the two quantities the D249 observation publishes). **g is piecewise linear, MONOTONE NON-DECREASING, knots at N = 0, 2, 4, 8, 16, with segment slopes m_j >= 0 on [0,2), [2,4), [4,8), [8,16), [16,inf), fitted by non-negative least squares.** The fitted **per-request delay at load N is m_j for the segment containing N.** The per-token term stays at the D162 value for pricing (b = 0.00018243 s per uncached token).
## Checks, pre-declared
1. Blocked bootstrap over 60 s blocks (respects serial correlation) for every m_j. 2. **Sufficiency of N: fit the 1x cells and the halved-memory cell SEPARATELY and pooled; report whether the curves agree.** If they do not, say so: a single curve in N then cannot serve both conditions. 3. Leave-one-cell-out R2. 4. **After the fit is frozen, report (do NOT use) its R2 on the s4 rung-3 cells as a held-out check.**
## Caveats stated now
Endogeneity: in-flight count rises when the engine is congested, so reverse causation inflates the slope; the in-flight set is reconstructed from the same request log that defines first-token latency (self-referential); one seed per halved-memory cell; the fit estimates the delay a request EXPERIENCES per request ahead, used as the delay a touch IMPOSES on those behind it.
**Output:** a JSON of the form `{knots, slopes m_j, a, b, c, data cells, this spec's commit}` committed before any `-q3` gate cell. The dry replay and the gate use that file unchanged.
