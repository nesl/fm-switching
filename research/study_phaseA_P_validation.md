## Mechanism of each miss (reported, NOT tuned)
1. **Host-store scope (the main cause for P-spec):** the spec model writes ALL blocks through to the host tier; the cell's own counters contradict it: kv_offload_store_bytes_total = 1.054e11 B = about 402k tokens (KV 262,144 B/token), against 5.09M engine-computed tokens of which robot 431k and dashcam 4.30M: the store volume matches ROBOT-ONLY computation within 7 percent. Under write-through dashcam traffic (about 85 percent of computed tokens) floods the shadow host LRU (381k shadow host evictions at n16 1x) and P predicts COLD for prefixes the engine had resident. The P-robot variant matches the measurement. **The vLLM rule that selects which blocks the connector stores was NOT found: the cause of the robot-only store is unidentified.** 2. **Question-tail granularity (all variants):** the shared prefix is estimated as frames x tokens per frame; the question tail after the images is 1 to 2 blocks, so cached estimates run slightly high (dash004 presents 1,056 tokens, 1,024 cached). 3. **Pinned in-flight blocks (n24, n32):** the shadow overshoots its capacity in 91k (n24) and 190k (n32) allocations; the engine would queue or preempt, so the shadow overstates other sessions' residency (the likely source of n32's 73 false-warm in P-robot); no effect on touches. 4. **cached_tokens blindness:** host hits are not separable per request (engine_actions.py:352-358); the `gpu_only` variant is worse everywhere (n16 1x recall accuracy 0.409); counting GPU + host is supported by the zero-cached rate of 0.8 percent against a host working set of 3.3x the tier. 5. **Status-quo belief failure mode:** the tier belief is built in the build path only and never demoted by eviction (the corrector runs observe-only), so it is warm for 99 percent of sessions after the first build and misses evicted ones: false-warm 36, 75, 70, 107, 135 across the five cells. 6. **Resync lag:** it changes shadow state on 8.3k to 0.9k requests but the request's own insert refills the chain: small effect.
**Sensitivity (diagnostic, no tuning), P-robot MAE / accuracy:** GPU +-10 percent: unchanged to 0.001 in every cell; host -10 / +10 percent: n16 1x 0.004 / 0.996 and 0.001 / 0.999; n16 3:11:2 0.034 / 0.962 and 0.010 / 0.991; halved 0.033 / 0.962 and 0.020 / 0.976; n24 0.057 / 0.944 and 0.042 / 0.958; n32 0.119 / 0.879 and 0.114 / 0.888; P-spec has the same shape. **The GPU capacity is nearly irrelevant: the host tier decides what the engine reports as cached.**
