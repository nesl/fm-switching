# Advisor story deck — plotted numbers and their sources (2026-10-23)

Generated by `experiments/figures/make_advisor_story_2026_10.py` at commit `c26f452a8483`. CPU only; no GPU was used and no inference was run. Loaders and statistics helpers are imported from `make_advisor_plots_2026_10.py`.

Every value is **computed from the committed result files** unless its source column names a report. The *report value* column is the figure printed in that report; a difference larger than the stated tolerance (0.1 pp by default) is flagged as a MISMATCH below and is never silently reconciled.

Confidence intervals: S-EMBER rows use the video-clustered bootstrap from `experiments/sember/study_o_q4_analyze.py` (2,000 resamples, seed 0); ERQA rows use a paired question-level bootstrap (2,000 resamples, seed 0); AUROC CIs reuse `experiments/erqa/r4_analyse.py`'s `auroc` and `boot_ci` and consume its random stream in that script's order.

## Notes

- **T2** — ERQA device arms are A6000 HF sdpa and the cloud arm is H100 HF fa2, so the ERQA device↔cloud gap is BACKEND-MISMATCHED, exactly as reports/study_r_device_vs_cloud.md labels it. ERQA device latency was never measured, so only S-EMBER carries a latency axis.
- **T4** — The S-EMBER latency multiple is measured on **batched** runs (R1 cells ran at concurrency 8 on the cloud side), so 1.7x understates what one 32B Thinking request costs on its own: K2's median completion length is 139 tokens against K1's 2. The ERQA multiples are single-request. The device S-EMBER row is the A6000 accuracy mirror; on the Jetson Orin itself the same contrast is 38.31 s / 17.07 s = 2.2x (see the first slide).
