# Windowed network scoring (netwin.py, netwin_pool.py): provenance note

Written 2026-11-27 by the flash session (a scoring subagent wrote the code under flash's brief; user ruling D332/D333). Read-only scoring code: it reads committed cell outputs from results/orchestration/live2/frozen_test/runs/<cell>/ (outcomes, request log, trace meta; fetched with `git show origin/main:<path>`) and writes text and JSON; it is NOT executed by the H100 run queue.

- `netwin.py <outage_dir> <control_dir> <t0> <d> <label> [--json out.json] [--window def1]`: harm = control MINUS outage over the FIXED window [R, R+120 s] (R = t0 + d) with sensitivity windows [R, R+60] and [R, R+300] (D333 item 1; B_obs DEF1 and DEF2 are printed as DESCRIPTIVE quantities; `--window def1` keeps the earlier per-cell B_obs window), the during-outage relief [t0, R] and the whole-run net beside. Fields = the committed scorer's (experiments/orchestration/live2/scorer/score.py): on-time = `_within(o, L)` (deadlines robot 3.0 s, single-shot 2.0 s, dashcam 1.0 s); robot cbd = robot_rows.standing_correct_by_deadline; robot cloud on-time = source_by_deadline == 'cloud'; single-shot on-time = assistive_rows.on_time; dashcam = `_within(o, 1.0)`. Question-clustered bootstrap (seed 7, 2,000 reps; dashcam clustered by 60 s blocks, 10 s blocks when the window is under 120 s). Positive control: the classifier reproduces the committed cbd per opportunity; run it before reading a result.
- `netwin_pool.py --a f1.json f2.json ... [--b g1.json ...] [--tag SUBSTR] [--out FILE]`: pools several --json outputs (clusters (seed, question) for robot and single-shot, (seed, block) for dashcam; seed 7, 2,000 reps); `--a` alone: pooled harm; `--a` and `--b`: the CI of harm_A minus harm_B (A = F0, B = rung 3 for the D331/D332 network pass rule), resampling each group independently.
- Self-tests so far: reproduces the n32 group A windowed re-score (B_obs 112 s, robot cbd +1 of 50); rung 3 n20 s4 at t0 483.5 (note research/study_netwin_rung3_n20_s4_w120.md); netwin_pool.py A-vs-A difference 0 for every metric. Pooled CIs differ by about 1 from per-cell CIs because the bootstrap draw order differs.
- Known limitations: DEF1 B_obs is unstable (bursty uncached traffic); few clusters at [R, R+120] for dashcam (3 one-minute blocks per seed): pool across seeds.
- Git: written but not committed by the flash session (git is read-only for it): pushed through the temp-index recipe at origin tip 68b25415; the committing user's later commit supersedes this provenance.
- `netwin_abs.py --a A1.json [A2.json ...] --b B1.json [...] [--windows 120,60,300,whole] [--out FILE]` (SECONDARY readout, D332 harm rule stays the verdict): pooled ABSOLUTE outage-cell difference A minus B (outage counts, not harm vs own control), per type (robot cbd, robot cloud on-time, SS on-time, dashcam within_L), windows [R,R+120], [R,R+60], [R,R+300] and whole run; each arm's own control counts beside. Paired cluster bootstrap over the union of clusters (seed, question)/(seed, block), seed 7, 2,000 reps. Reads the per-unit `rec` of netwin.py --json (whole-run units already stored; netwin.py unchanged). Adding s5/s6: same command with more jsons on each side, e.g. --a f0_s4.json f0_s5.json f0_s6.json --b rung3_s4.json rung3_s5.json rung3_s6.json (each json carries its seed).
